# Support

## Getting Help

Clean support is currently **best-effort**. The canonical public channel is **GitHub Issues**:

1. **Bug reports**: Open an issue with the `bug` label describing the issue, steps to reproduce, and expected behavior.
2. **Feature requests**: Open an issue with the `feature` or `enhancement` label describing the desired functionality.
3. **Questions**: Open an issue with the `question` label.

If the problem is obviously documentation or install/toolchain related, say that in the title and include the exact commands you ran. For current CLI state, run `clean --help` from a local build.

## Security Issues

For security vulnerabilities, **do not** open a public issue. Instead, see [SECURITY.md](SECURITY.md) for responsible disclosure instructions.

## Communication Channels

- **Primary**: GitHub Issues on this repository
- **Security**: [SECURITY.md](SECURITY.md)

Private trackers, maintainer-only discussion rooms, and internal status
threads are not public Clean support channels. If a maintainer references one
of those systems, ask them to mirror the user-facing status back to the Clean
GitHub issue.

## Issue Response

Issues are triaged and prioritized by project maintainers, but there is **no response-time SLA**. Labels indicate queue priority, not a guaranteed human turnaround. Security issues should follow [SECURITY.md](SECURITY.md); public trust/correctness concerns should include the smallest reproducible example and the exact theorem/command path involved.
