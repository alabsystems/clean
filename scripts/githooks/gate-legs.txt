# Clean pre-push leg policy — the single place that says which `local_gate.sh
# --fast` legs the pre-push hook runs, and why the others are left out.
#
# Author: Andrew Yates. Copyright 2026 Andrew Yates. License: Apache-2.0.
#
# WHY THIS FILE EXISTS
# --------------------
# The hook cannot be `local_gate.sh --fast` verbatim. Measured 2026-08-23 at
# 97efa0e6c on a pinned worktree, `--fast` is ~40 s warm and minutes cold, three
# of its legs are cargo builds, and three of them were RED at HEAD for reasons
# no pusher caused. A hook like that does not get a gate installed; it gets
# `--no-verify` installed. So the hook runs a curated subset and this table
# records the curation, one row per leg, reviewed like any other tracked file.
#
# Read that measurement literally: `--fast` is NOT a 30-second budget and never
# was. It still compiles the trusted kernel twice and the CLI once
# (soundness-cert, axiom-audit-consistency, cli-feature-coverage — 410.8 s,
# 8.0 s and 293.3 s COLD respectively). Those legs are excluded from the HOOK,
# which is what COST means; they are NOT excluded from `--fast`, and the MODE
# column now says so on every row instead of leaving prose to imply otherwise.
# Comments elsewhere in local_gate.sh that speak of a "<30 s --fast path" are
# describing an intent, not this tree.
#
# It is also the anti-drift record. `scripts/check_hook_coverage.py` fails
# closed unless the ids here are EXACTLY the `# GATE-LEG:` ids reachable in
# local_gate.sh's fast path AND exactly the ids the hook declares. A new fast
# leg is therefore a build error until somebody classifies it here — which is
# the one thing a hand-curated subset would otherwise silently lose.
#
# FORMAT — one row per leg, `|`-separated:
#     <status> | <mode> | <leg-id> | <owner> | <expires YYYY-MM-DD> | <reason>
# Blank lines and lines whose first non-space character is `#` are comments.
#
# THE TWO COLUMNS ANSWER TWO DIFFERENT QUESTIONS, and conflating them is a
# defect this table shipped with. STATUS is about the HOOK. MODE is about
# `local_gate.sh`. Until 2026-08-25 there was only STATUS, and five of the six
# COST rows asserted "Full gate only" about legs that sat outside every
# `GATE-FULL-ONLY` region in local_gate.sh and therefore ran in `--fast` as
# well. Nothing checked it, because the checker only ever compared NAMES.
#
# STATUS is one of three, and the difference is the whole point:
#
#   IN_HOOK   The hook runs it and a failure REFUSES the push. owner/expires
#             are `-`. Every row here was measured green and cheap at the
#             timestamp in the reason.
#
#   COST      Deliberately not in the HOOK because it is too slow or reaches
#             outside this repo. Permanent, so owner/expires are `-`, but the
#             reason MUST carry the measured cost — a cost exclusion with no
#             measurement is not reviewable. It says NOTHING about which
#             local_gate.sh mode runs the leg; that is the MODE column's job,
#             and four COST rows are `both`.
#
#   WAIVED    Cheap enough for the hook but currently RED for a reason the
#             pusher did not cause. The hook STILL RUNS IT and prints the
#             failure; it just does not block. Requires a real owner and a
#             real expiry. Two ways it bites back: an EXPIRED waiver blocks the
#             push, and a waiver whose leg has gone GREEN blocks the push and
#             asks to be deleted, so it cannot outlive its problem.
#
# MODE is one of two, and it is DERIVED, not declared — `check_hook_coverage.py`
# reads it back out of local_gate.sh from where the leg's `# GATE-LEG:` marker
# sits, and refuses the push when the row disagrees:
#
#   both      `scripts/local_gate.sh --fast` runs it, and so does full mode.
#             The marker sits outside every `GATE-FULL-ONLY` region.
#
#   full      ONLY `scripts/local_gate.sh` (no `--fast`) runs it. The marker
#             sits inside a `GATE-FULL-ONLY` region, and fast mode prints a
#             SKIPPED line naming the reason.
#
# IN_HOOK and WAIVED force `both`: the hook is a subset of the fast path, so it
# cannot run a leg the fast path never reaches.
#
# There is no third mode, no fourth status, and no environment variable that
# turns a row off. The only way past the hook is `git push --no-verify`, which
# is git's own and shows up in the reflog rather than in a habit.
